# Эксплуатация

Установка только в контейнерах: Docker Compose через `./install.sh`, профили `standalone` и `shared-host`.
Приложение — пакет `llmp` на Python в образе `app`.

## Требования

| | |
|---|---|
| ОС | Linux x86_64/aarch64 (Ubuntu 22.04+, Debian 12+) |
| ПО | Docker Engine 24+ с Compose v2; в `standalone` установщик ставит их сам (apt) |
| ОЗУ | не меньше 3 ГБ с голосовым вводом (замер: весь стек с GigaAM ~2 ГБ), 2 ГБ без него (`--no-voice`) |
| Диск | 12 ГБ (образы ~4 ГБ, модели ASR ~0,5 ГБ, данные, резервные копии) |

## Установка

```bash
git clone https://github.com/calleograph/llm-provider.git /opt/llm-provider
cd /opt/llm-provider
./install.sh --dry-run          # предпросмотр всех изменений
sudo ./install.sh               # мастер: профиль, каталоги, имя проекта, порт, публикация
```

| Профиль | Что делает установщик |
|---|---|
| `standalone` (выделенный сервер) | проверяет ОС/ресурсы, при необходимости ставит Docker, Compose и nginx (apt, без обновления системы); публикация — свой сайт nginx (TLS: `--tls-cert/--tls-key`) или порт приложения (`--bind 0.0.0.0 --port 8084 --publish port` — доступ по `http://IP:8084`) |
| `shared-host` (сервер с другими проектами) | ничего не ставит; не хватает Docker — диагностика и остановка; порт только на `127.0.0.1`, свободный подбирается автоматически; публикация — свой файл сайта nginx (`--publish nginx`, `nginx -t`, откат своих изменений) или внешний прокси (`--publish port`) |

В обоих профилях: отдельный Compose-проект (`--project`, проверка уникальности), свои сети и тома, данные в `--data-root`
вне каталога кода, секреты в `.env` (600), чужие контейнеры, сети, образы, сайты и файрвол не изменяются, глобальная
очистка Docker не выполняется. Повторный запуск безопасен (секреты и параметры сохраняются, свой порт считается свободным).
Этапы: `preflight ports dirs config models build start verify admin nginx summary`; продолжить с места сбоя — `--from ЭТАП`.

Параметры: `--profile`, `--data-root`, `--project`, `--port`, `--bind`, `--public-url`, `--publish port|nginx`, `--server-name`,
`--tls-cert`, `--tls-key`, `--models-from КАТАЛОГ` (закрытая сеть), `--no-voice` (без ASR), `--yes`, `--dry-run`, `--from`.

## Ресурсы

Этап `config` подбирает число процессов и лимиты памяти по объёму ОЗУ сервера (замер: ASR с GigaAM ~1,5 ГБ,
обезличивание ~0,2 ГБ, процесс приложения ~0,1 ГБ). Значение в `.env` меняется, только если там ещё стоит значение
из `.env.example` (ваши правки не перезаписываются).

| ОЗУ | `APP_WORKERS` | `APP_MEM_LIMIT` | `ANON_MEM_LIMIT` | `ASR_MEM_LIMIT` |
|---|---|---|---|---|
| 7,5 ГБ и больше | 4 | 2g | 1536m | 4g |
| 5–7,5 ГБ | 2 | 1g | 1g | 2g |
| меньше 5 ГБ | 2 | 640m | 768m | 1800m |

При нехватке памяти на сервере ядро завершает сначала `asr` (`oom_score_adj: 500`, перезапускается сам), затем
`anonymizer` (`300`), а не соседние службы сервера.

Службы Compose-проекта:

| Служба | Что делает |
|---|---|
| `nginx` | единственный опубликованный порт (`APP_BIND:APP_PORT`); статика `public/assets`, прокси в `app`, WebSocket `/ws/dictation` → `asr` |
| `app` | веб-приложение: Uvicorn + FastAPI (`llmp.web.main:app`), пользователь `www-data` (uid 33), `read_only`; число процессов — `APP_WORKERS`, память — `APP_MEM_LIMIT` |
| `scheduler` | тот же образ, `python -m llmp.scheduler`: очередь писем раз в минуту, ротация журналов и удаление истёкших сессий раз в час |
| `anonymizer` | сервис обезличивания; только внутренняя сеть, без выхода в интернет |
| `redis`, `asr` | голосовой ввод (профиль Compose `voice`; без него — `--no-voice`) |

Веса распознавания речи GigaAM (`<модель>.ckpt` и `<модель>_tokenizer.model`) скачивает `scripts/models.sh`; его вызывают
установщик, обновление и помощник обновлений, а вручную — `./scripts/ctl.sh models`. Источники по порядку: зеркало проекта
на GitHub (Releases, тег `models-gigaam-v3`), свой `GIGAAM_MODEL_BASE_URL` из `.env`, CDN разработчика модели (у него
сертификат истёк 2026-11-04, поэтому он сейчас резервный; проверку сертификата скрипт не отключает). Для модели по
умолчанию сверяется SHA-256, страница прокси вместо файла отклоняется. Если весов нет, они появятся при установке или
обновлении сами. Закрытая сеть: скачайте оба файла на другом компьютере и выполните
`./scripts/ctl.sh models --from-dir КАТАЛОГ` (при установке — `--models-from КАТАЛОГ`).

После установки: войти в `/admin/` (логин и пароль аварийного администратора печатаются один раз; сброс —
`scripts/ctl.sh admin-reset`), добавить LDAPS-подключение, группы AD, подключения LLM и модели.
Для кнопок обслуживания и обновления в админке: `sudo scripts/updater.sh install` (служба работает от имени владельца каталога с кодом,
ему нужна группа docker; каталог обмена запросами приложению доступен только для записи запроса, состояние — только на чтение).

Перенос установки 1.x (хостинг без контейнеров): запустите `install.sh` в её каталоге — `var/data` (БД, сертификаты)
переносится в каталог данных, мастер-ключ `var/data/master.key` — в `.env`; исходные файлы не удаляются.

## HTTP, HTTPS и прокси

- Доступ по `http://IP:порт` работает без HTTPS: перенаправлений на https и HSTS нет, cookie сессии получает флаг `Secure`
  только при HTTPS или заголовке `X-Forwarded-Proto: https`.
- HTTPS — на любом reverse proxy перед сайтом (системный nginx, Nginx Proxy Manager и т. п.). Адрес прокси укажите в админке:
  **Система → Настройки → Доверенные reverse proxy**. Только от доверенных адресов
  учитывается `X-Forwarded-For` (адрес клиента для журнала и ограничения попыток входа).
- Голосовой ввод браузер разрешает только в защищённом контексте (HTTPS или `localhost`). По обычному http кнопка микрофона
  не работает, и чат показывает подсказку «Голосовой ввод — только по HTTPS».
- Для проверки Origin диктовки и ссылок в письмах задайте публичный адрес: `APP_PUBLIC_URL` в `.env`.

## Доступ администратора

Установщик печатает логин `admin` и пароль один раз. Если пароль потерян:

```bash
./scripts/ctl.sh admin-reset
```

Команда вызывает `python -m llmp.cli admin-reset --text`, печатают новый пароль и завершают все открытые сессии
администратора. Если администратора в БД нет, `/admin/` открывает одноразовую форму первого запуска (`/admin/setup.php`) —
до этого ограничьте доступ к сайту сетью администраторов. Сессия администратора — не дольше 24 часов бездействия
(по умолчанию 4 часа, настраивается в «Настройки»). Если AD ещё не настроен, форма входа сразу предлагает локального администратора.

## Обслуживание

| Команда | Назначение |
|---|---|
| `scripts/ctl.sh status [--json]` | службы, версия, диск |
| `scripts/ctl.sh preflight` | Docker, каталог данных, место, порт, права `.env` |
| `scripts/ctl.sh verify` | службы healthy, `python -m llmp.cli verify` в `app`: целостность БД, готовность моделей обезличивания и ASR |
| `scripts/ctl.sh smoke` | страница, API без входа, недоступность исходников, обезличивание, изоляция сервиса обезличивания, тестовое распознавание (адрес — из `APP_BIND`) |
| `scripts/ctl.sh logs [служба] [N]` | журналы с маскированием секретов |
| `scripts/ctl.sh diag` | архив диагностики (секреты замаскированы, значения из `.env` вычищены) |
| `scripts/ctl.sh repair` | права каталогов, перезапуск нездоровых служб своего проекта |
| `scripts/ctl.sh start / stop / restart / admin-reset` | |

Служебные команды приложения (их вызывают скрипты; вручную — внутри контейнера `app`):

| Команда `python -m llmp.cli …` | Назначение |
|---|---|
| `admin-reset [--text]` | создать администратора `admin` или задать новый пароль; JSON или строка для человека |
| `admin-exists` | код выхода 0 — администратор есть |
| `verify` | целостность БД, готовность обезличивания и ASR (ждёт загрузки моделей до 90 с) |
| `smoke-anon` | ФИО, телефон и пароль должны быть заменены → `CLEAN` или `LEAK` |
| `snapshot ПУТЬ` | согласованный снимок БД (`VACUUM INTO`) |
| `counts ПУТЬ ТАБЛИЦА…` | число строк в таблицах снимка (JSON) |

Планировщик (`python -m llmp.scheduler`) раз в час, кроме ротации журналов и сессий, удаляет записи
телеметрии (`llm_outbound`) старше срока из «Аудит и DLP → Правила и хранение» (по умолчанию 365 дней, 0 — хранить
бессрочно) — порциями по 2000, вместе с поисковым индексом и срабатываниями DLP. Каждую минуту он же продолжает
перепроверку журнала правилами DLP, если она поставлена (после правки правила — за 7 дней; вручную — за 7, 30 дней
или весь журнал), порциями по 5000 записей не дольше 20 секунд. Таблица телеметрии не входит в ротацию журналов по объёму; при большом числе пользователей
следите за размером БД и при необходимости сокращайте срок.

## Обновление и откат

`scripts/check-updates.sh [--ref ТЕГ|ВЕТКА]` — есть ли обновление: только `git fetch`, ничего не меняет. Печатает канал,
установленную и доступную версию, новые коммиты, новые ключи `.env` (только имена). Код возврата: `0` — обновлений нет,
`10` — есть, `1` — проверить не удалось.

**Из админки — раздел «Система → Обновление»**: установленная версия, что опубликовано на GitHub (с перечнем изменений),
кнопки «Проверить обновления» и «Обновить до X». Запросы выполняет помощник `updater.sh` (`check` → `check-updates.sh`,
`update` → `update.sh --yes`); ход работы он пишет построчно в `DATA_ROOT/updater/live-output.txt`, страница показывает его
и перечитывается сама, дожидаясь сервера, пока приложение перезапускается. После обновления помощник перезапускает себя
из нового кода. Итог последней проверки запоминается в `app_settings` (`update_last_check`).

`scripts/update.sh [--dry-run] [--yes] [--force] [--ref ТЕГ|ВЕТКА] [--recover]`. Канал определяется по установке:
установка с тега (`git clone --branch vX.Y.Z`, HEAD отсоединён) обновляется до самого нового тега `vX.Y.Z` из origin
(токен GitHub не нужен); установка с ветки — перемоткой до `origin/<ветка>`; `--ref` — явная цель. Порядок: автопочинка git →
список новых коммитов и ключей `.env` → (`--dry-run` — только план) → preflight, verify, место на диске → сохранение
локальных правок и коммитов → резервная копия → прежние образы помечаются тегом прежнего коммита → переход (`merge --ff-only`
или `checkout --detach`, `reset --hard` никогда) → новые ключи `.env` дописываются → сборка (старая версия работает) →
запуск, healthcheck, verify, smoke → отчёт `DATA_ROOT/updater/report.txt` и `history.jsonl`. Сбой сборки — код возвращается;
сбой после переключения — автоматический откат на прежние образы. Прерванное обновление обнаруживается при следующем
запуске: `--recover`. Скрипт целиком в функциях: git может заменить его файл во время работы.

Автопочинка (`scripts/lib/autorepair.sh`): зависшие `.git/*.lock` старше минуты (если в каталоге не работает git) снимаются;
«dubious ownership» — `safe.directory` только для этого каталога и только в окружении процесса (глобальный git-конфиг не
меняется); fetch с повторами и таймаутами; мелкий клон догружается (`fetch --unshallow`); правки отслеживаемых файлов
сохраняются в `${BACKUP_DIR:-DATA_ROOT/backups}/local-changes-<время>/` (`changes.patch`, `files.tar.gz`, инструкция возврата)
и в `git stash`; локальные коммиты, которых нет в цели, — там же (`local-commits.bundle`) и в `refs/llmp/saved/*`.
Неотслеживаемые файлы и `.env` не трогаются. Тесты: `bash tests/scripts/update_test.sh`.

`scripts/rollback.sh [КОММИТ]` — откат без пересборки (ветка остаётся веткой, канал обновлений не меняется). Схема БД только расширяется, поэтому прежняя версия работает
с текущей БД; полный возврат данных — `scripts/restore.sh`.

### Обновление с 1.x до 2.x

Тот же `scripts/update.sh`. Образ `php` 1.x сохраняется под тегом прежнего коммита, вместо него собирается образ `app`.
Переносятся без конвертации: БД (та же схема, миграции выполняются при старте процесса и не берут блокировку записи на
готовой БД), мастер-ключ и сохранённые секреты, хеши паролей, история, сертификаты. Сессии теперь хранятся на сервере, поэтому
пользователи и администраторы один раз входят заново. Возврат на 1.x — `scripts/rollback.sh` (образ `php` прежнего коммита).

## Резервные копии

`scripts/backup.sh` — снимок БД (`python -m llmp.cli snapshot`, `VACUUM INTO`, без остановки), сертификаты, `.env`,
манифест с SHA-256 и счётчиками таблиц; шифрование GPG AES-256 ключом `.backup.key` (в образы и git не попадает — храните
его копию вне сервера); копия сразу проверяется, ротация `--keep N` (по умолчанию 14) удаляет только копии своего проекта.
`--verify ФАЙЛ`, `--restore-test ФАЙЛ` (расшифровка, целостность и счётчики БД во временном каталоге).
`scripts/restore.sh ФАЙЛ [--with-env]` — проверка → страховочная копия → замена данных → verify; с `--with-env`
конфигурация из копии перечитывается перед запуском.

## Что проверено

Установка и обновление проверяются на отдельном сервере с другими работающими контейнерами: установка в режиме shared-host
не затрагивает чужие контейнеры и сайты; обновление, откат, автоматический откат неудачной версии, восстановление после
прерванного обновления, копирование и восстановление данных, отказ при повреждённой копии или чужом ключе.
