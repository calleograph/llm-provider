# Проекты: как устроены и почему так

Проект — общий контекст для группы чатов: инструкции, материалы, память и настройки. Схема взята из
Hermes Agent (Nous Research) и продуктов ChatGPT/Claude Projects и перенесена на наш стек с одним
жёстким условием: всё, что уходит в модель, обезличено.

## Что делает Hermes

Изучен репозиторий https://github.com/NousResearch/hermes-agent (коммит 7bc32b575f, v0.22.2), страницы
`website/docs/developer-guide/prompt-assembly.md`, `.../context-compression-and-caching.md`,
`website/docs/user-guide/features/memory.md` и `.../context-files.md`, код `agent/prompt_builder.py`,
`agent/system_prompt.py`, `agent/context_compressor.py`, `tools/memory_tool.py`.

- **Системный промпт собирается тремя ярусами: stable → context → volatile.** Stable — личность и
  правила, context — файлы проекта (`.hermes.md` / `AGENTS.md` / `CLAUDE.md`), volatile — снимок памяти,
  время, окружение. Причина — кэш промптов у провайдера: он переиспользует самый длинный общий префикс,
  поэтому изменчивое идёт в конце. Внутри яруса context общие для проекта файлы идут раньше всего, что
  зависит от конкретного рабочего каталога.
- **Инструкции проекта — один файл.** Загружается только один тип файла (побеждает первый найденный),
  он режется по лимиту (70 % начала + 20 % конца, лимит растёт с окном модели, минимум 20 000 знаков) и
  проверяется на внедрение команд. Вложенные `AGENTS.md` подгружаются только когда агент заходит в их
  каталог — промпт не раздувается.
- **Память — два маленьких хранилища с жёстким лимитом:** `MEMORY.md` (2 200 знаков — факты среды и
  проекта) и `USER.md` (1 375 знаков — профиль пользователя). Показ в промпте с заполненностью
  («67 % — 1 474/2 200»). Сама память не сжимается: при переполнении модель сама объединяет записи.
  Снимок памяти фиксируется в начале сеанса и посреди него не меняется — ради кэша. Пользователь может
  смотреть, править и удалять записи (`/journey`), включать подтверждение записи (`write_approval`),
  выключать память совсем (`memory_enabled: false`).
- **Сжатие истории.** Основной компрессор срабатывает при 50 % окна, страховка шлюза — при 85 %.
  Хвост свежих сообщений сохраняется дословно, остальное сворачивается в структурированную сводку
  (текущая задача, цель, ограничения, факты, решения, сделано, открытые вопросы). Сбой сводки не ломает
  диалог: пауза 60 → 300 → 900 с, затем запасная сводка. Учёт токенов — по данным провайдера, оценка —
  только как запасной вариант.
- **Кэш промптов.** Точки кэша: системный промпт + три последних сообщения. Смена модели посреди
  диалога обнуляет кэш, поэтому Hermes не переключает модель молча.
- **Настройки «на проект»** в Hermes — профили (отдельные config, память и навыки), а также правила
  в `.hermes.md`.

**ChatGPT Projects / Claude Projects** (для сравнения): у проекта есть инструкции (важнее личных
настроек), файлы-знания (если не помещаются в окно, Claude ищет по ним подходящие фрагменты), память
в пределах проекта, которую можно посмотреть и отредактировать, и чаты проекта.

## Что было у нас

- Инструкции — только именованные блоки; прежнее единое поле при каждом открытии переносилось в блок,
  блоки нельзя было править, только удалять и добавлять заново.
- «О проекте» — описание и «Состояние работы» только для чтения: исправить или очистить
  автоматическую память было нельзя, выключить — тоже.
- Источники — целиком или фрагментами, но доля окна была зашита (40 %), и пользователь не видел,
  сколько контекста съедает проект.
- Порядок блоков в промпте: состояние → сводка → источники. Изменчивая сводка шла перед большими
  неизменными источниками, и кэш провайдера на них не срабатывал.
- Настроек проекта не было: модель и стиль у каждого чата выбирались заново.

## Что изменили и почему

| Часть | Сейчас | Откуда идея |
|---|---|---|
| Инструкции | Основная инструкция — одно редактируемое поле (до 8 000 знаков, `llm_projects.instructions_z`) + описание одной фразой + необязательные блоки со своими лимитами. В промпте основная инструкция идёт перед блоками. Перенос старого поля в блоки удалён: поле снова и есть основная инструкция, уже перенесённые блоки остаются блоками | один файл инструкций у Hermes, Project instructions у ChatGPT/Claude |
| Материалы | Бывшие «Источники». Целиком, если помещаются; иначе — подходящие к вопросу фрагменты без повторов. Гарантированная доля окна настраивается: 20/40/60/80 %. Можно выключить | файлы-знания Claude + бюджет окна у компрессора Hermes |
| Память проекта | Бывшее «Состояние работы» (`state_z`). Ведётся автоматически после сворачивания длинного чата в сводку (до ~600 токенов). Пользователь видит заполненность (знаки / 4 000) и дату обновления, может исправить (правка обезличивается) или очистить. Выключатель: память не передаётся и не обновляется | `MEMORY.md` Hermes (лимит, видимая заполненность, правка, выключение), память проекта у ChatGPT/Claude |
| Настройки | `llm_projects.settings` (JSON): модель для новых чатов, стиль ответа (чат → проект → пользователь → администратор), передавать ли материалы и память, доля под материалы. Модель проверяется по правам пользователя, стиль — по списку разрешённых | профили Hermes |
| Порядок промпта | Слои 1–6 → материалы целиком → память → сводка → фрагменты под текущий вопрос. Неизменная часть — общий префикс запросов всех чатов проекта | ярусы stable → context → volatile |
| Учёт токенов | Вкладка «Настройки» показывает, сколько проект добавляет к каждому запросу (инструкции, память, материалы, всего и % окна выбранной модели) и предупреждает, если материалы будут идти фрагментами. В отчёте под ответом память и сводка показаны отдельно | учёт контекста Hermes |
| Сжатие | Как и раньше: сводка ранней части диалога после ответа, когда история не помещается или занимает больше 60 % своей доли; память проекта обновляется из этой сводки, только если включена | компрессор Hermes |

Обезличивание: описание, основная инструкция, блоки (название и текст), материалы (название и текст) и
правка памяти проходят через сервис обезличивания до сохранения. Автоматическая память строится из уже
обезличенной сводки. Название проекта в модель не передаётся. Тест
`test_every_project_field_reaching_the_llm_is_anonymized_and_settings_apply` проверяет это на каждом поле.

API (`api.php`): `GET project` дополнительно отдаёт `project.settings`, `project.state_updated_at`,
`memory_limit`, `context_tokens`; `POST project_update` дополнительно принимает `instructions`,
`memory` (пусто — очистить) и `settings` (JSON). Остальные поля и ответы прежние.

## Что сознательно не сделано

- **Самостоятельная запись памяти моделью (инструмент `memory`, как у Hermes).** У нас нет вызова
  инструментов, и модели пришлось бы видеть больше, чем нужно. Память обновляется из сводки — дёшево и
  предсказуемо.
- **Векторный поиск по материалам и кэш нарезки.** Нарезка нескольких десятков тысяч знаков при каждом
  запросе занимает миллисекунды; лимит материалов — 30 000 знаков по умолчанию. Если лимит поднимут до
  мегабайт — сохранять куски при загрузке.
- **Точки `cache_control` для Anthropic.** Порядок промпта уже подходит для автоматического кэша префикса
  (OpenAI-совместимые провайдеры); явные точки — отдельная задача адаптера.
- **Обновление памяти по коротким чатам.** Память обновляется только после сводки, то есть по
  длинным чатам. Короткие чаты в неё не попадают — экономия токенов; при необходимости пользователь
  дописывает факты вручную.
