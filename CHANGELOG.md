# CHANGELOG

## 2.0.0 — 2026-11-15

Приложение переписано с PHP на Python. Поведение, адреса, интерфейс и данные сохранены.

### Добавлено

- Оформление «Переговорки»: темы «Стекло» (по умолчанию) и «Тёмная», выбор в боковой панели чата и админки,
  «Настройки → Оформление → Тема по умолчанию для всех»; шрифты Inter и Manrope.
- Телеметрия: журнал всех запросов во внешние нейросети (кто, когда, модель, токены, ушедший текст) независимо от удаления
  чатов, раздел админки «Телеметрия» с CSV-выгрузкой, аудит каждого просмотра чужих данных, метка «Ведётся телеметрия» в чате.
- Проекты по образцу Hermes: основная инструкция, материалы с долей окна, редактируемая память проекта, настройки проекта
  (модель, стиль, выключатели), учёт токенов проекта, порядок промпта для кэша провайдера.
- Обезличивание быстрее: короткое сообщение ~11 мс вместо 30, при 2 CPU в 3–4 раза быстрее; этапы ожидания в чате.
- Обновление с GitHub по образцу «Переговорки»: `scripts/check-updates.sh` (только проверка), в `update.sh` — автопочинка
  git (зависшие блокировки, «dubious ownership», мелкий клон, повторы сети), сохранение локальных правок и коммитов
  в резервный каталог, канал релизов (новейший тег `vX.Y.Z`) и канал ветки; скрипт читается целиком до выполнения.
- Установщик сам подбирает число процессов приложения и лимиты памяти по объёму ОЗУ сервера (меньше 7,5 ГБ —
  `APP_WORKERS=2` и пониженные лимиты; значения, изменённые вручную, не трогаются). Голосовому вводу нужно 3 ГБ ОЗУ,
  без него — 2 ГБ. При нехватке памяти ядро завершает сначала `asr` и `anonymizer` (`oom_score_adj`), а не соседние службы.
- Служебные команды `python -m llmp.cli admin-reset [--text] | admin-exists | verify | smoke-anon | snapshot | counts`.
- Подсказка в чате, что голосовой ввод работает только по HTTPS (браузер не даёт микрофон странице по http).

### Изменено

- Стек: Python 3.13 в образе, FastAPI + Uvicorn, Jinja2, sqlite3, cryptography, argon2-cffi/bcrypt,
  ldap3, httpx, defusedxml. Образ `app` вместо `php`; служба `scheduler` — `python -m llmp.scheduler`.
- Адреса прежние (`index.php`, `api.php`, `admin/index.php?section=…`, `admin/setup.php`, `healthz.php`) — теперь это
  маршруты приложения; браузерный код и стили не менялись. Код и данные по HTTP недоступны при любой настройке nginx.
- Та же схема БД, миграции при старте процесса без блокировки записи на готовой БД; SecretBox (AES-256-GCM) в прежнем
  формате; хеши паролей PHP-версии проверяются как есть.
- Сессии хранятся на сервере (таблица `web_sessions`). Cookie получает `Secure` только при HTTPS или
  `X-Forwarded-Proto: https` — доступ по `http://IP:порт` работает, HTTPS — через любой прокси.
- Исходящие запросы: TLS проверяется всегда, доверие — системное хранилище сертификатов, корпоративный CA — из
  «Сертификатов». Сессия администратора — не дольше 24 часов бездействия.
- `.env`: `PHP_FPM_MAX_CHILDREN`/`PHP_MEM_LIMIT` заменены на `APP_WORKERS`/`APP_MEM_LIMIT`.
- Тесты: pytest (около 450), таблица соответствия всем 202 тестам PHPUnit — `tests/PARITY.md`; сквозной стенд `tests/e2e`.

### Исправлено

- Названия источников и блоков инструкций проекта теперь обезличиваются.
- Ответ на сообщение, отправленное без обезличивания, помечается так же и повторно не отправляется; такие сообщения
  уходят только выбранной модели, без резервных.
- Сводки диалога учитывают настройку автоматического резервирования (`fallback_auto`) и списываются с лимита.
- Токены резервируются до обращения к LLM и возвращаются при ошибке (в 1.x возврат не работал).
- Помощник обслуживания: каталог обмена недоступен приложению на запись (кроме запроса), помощник работает от имени
  владельца репозитория.
- `.backup.key` исключён из образов и git.
- Ротация журналов — по размеру таблиц журналов, а не всей БД.
- Письмо, которое не удаётся расшифровать, больше не блокирует очередь.
- Отказ модели по фильтру содержимого не ставит модель на паузу.
- Лимит OCR распространяется на изображения внутри DOCX/ODT; пути к программам OCR проверяются.
- Очистка неактивных пользователей стирает и сводки, и состояние проектов.
- При смене адреса LDAP-сервера или провайдера сохранённый пароль/ключ API стирается.
- Сброс пароля администратора завершает его открытые сессии.
- `restore.sh --with-env` перечитывает конфигурацию перед запуском; `ctl.sh smoke` учитывает `APP_BIND`.
- Пароль Redis не виден в аргументах процессов.
- Ротация резервных копий не удаляет копии другого экземпляра с похожим именем.
- Веса GigaAM: SHA-256 необязателен, проверяются размер и формат (страница прокси вместо файла отклоняется), ошибка TLS
  называется явно. Сертификат CDN истёк 2026-11-04 — используйте `--models-from` или зеркало.
- Пароль администратора терялся при установке 1.0.0 (разбор JSON в bash) — установщики печатают его через
  `llmp.cli admin-reset --text`.
- Форма входа в админку предлагает локального администратора, если AD не настроен.
- Тап-цели 44 px на узких экранах.

### Удалено

- PHP-код: `src/`, `bin/`, `templates/*.php`, `public/*.php`, шлюзы в корне, `config/*.conf`, PHPUnit-тесты.
- Установка на PHP-хостинг и любая установка без контейнеров: только Docker Compose (`./install.sh`).
- Удалено: DocClean и внешние API обезличивания — одно встроенное обезличивание. Раздел админки «Обезличивание»
  показывает состояние сервиса, настройки движка, обработку файлов и лабораторию; сохранённые настройки внешних
  режимов не читаются.

### Переход с 1.x

- Docker: `scripts/update.sh` — резервная копия, сборка новых образов при работающих старых, автооткат при сбое. Данные,
  мастер-ключ, секреты, хеши паролей и история переносятся; пользователи один раз входят заново (сессии стали серверными).
  Возврат на 1.x — `scripts/rollback.sh`. Проверено: 1.0.0 → 2.0 с данными и обратно.
- Установка 1.x на PHP-хостинге: `install.sh` в её каталоге переносит `var/data` и мастер-ключ в установку Docker.

## 1.0.0 — 2026-11-15

Модернизация в самостоятельно устанавливаемый LLM-провайдер.

- Установка и обновление через Docker Compose: выделенный сервер и сервер с другими проектами, предпросмотр изменений,
  обновление с резервной копией и автоматическим откатом, зашифрованные резервные копии, диагностика.
- Обезличивание выполняется на вашем сервере: люди, организации, адреса, телефоны, почта, IP, серверы, учётные записи,
  ИНН/СНИЛС/ОГРН, карты и счета, договоры, суммы, словарь организации; пароли и ключи — всегда. Результат проверяется повторно,
  при сомнении запрос не отправляется. В админке — проверка «что уйдёт в нейросеть» для текста и документов.
- Голосовой ввод: кнопка микрофона в поле сообщения, распознавание на сервере, текст можно поправить перед отправкой.
- Несколько моделей у одного провайдера и выбор модели в чате; если модель не ответила или ответила пустым текстом,
  ответит резервная — в чате это видно.
- Длинные диалоги и большие проекты: в модель уходит то, что помещается в её окно — свежая история, сводка ранней части,
  подходящие фрагменты источников; под каждым ответом виден расход токенов.
- Проекты: описание и автоматически обновляемое состояние работы (факты, решения, открытые задачи).
- Стиль ответа (краткий, подробный, технический, деловой и др.), инструкции для чата и личные постоянные инструкции.
- Почтовые уведомления администраторам о проблемах моделей.
- Поддержка ODT; в DOCX учитываются примечания; изображения внутри документов распознаются или документ блокируется.
